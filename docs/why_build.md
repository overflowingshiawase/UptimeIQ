# Why Build — UptimeIQ的商業論證

## 一句話價值主張
UptimeIQ讓中小型製造業不需要導入昂貴CMMS系統，就能把設備異常判斷跟班別交接這兩件目前依賴人工記憶與習慣的事，變成有規則可循、有紀錄可查的自動化流程。

## 目標使用者輪廓與情境故事

**人物畫像**：陳班長，某中小型電子材料廠早班線長，負責監督5-8台機台（壓合機、CNC車床、空調主機等），有10年產線經驗，不熟悉複雜系統操作，習慣用LINE群組口頭交接。

**Before（現況）**：陳班長每天早上接班，要靠記憶和翻閱手寫保養紀錄本，判斷哪台機台「感覺快要出問題」。交接時，前一班的人有時候寫得很詳細，有時候只丟一句「正常」就走了，如果當天真的出狀況，陳班長常常要花時間回頭問前一班的人到底發生什麼事，或是等問題擴大了才發現。

**After（使用UptimeIQ後）**：陳班長一到班，系統已經根據保養間隔規則自動算出哪幾台機台風險偏高，並且已經推播了一段白話的診斷說明，陳班長不用自己判斷、也不用翻紀錄本。前一班的交接紀錄不管寫得詳細或簡短，系統都已經整理成固定格式，如果內容太簡略還會被標記出來。

## 量化痛點與ROI邏輯（延伸BRD-02停機成本試算框架，模擬情境）

**異常診斷推播的價值**：假設一次未被及時發現的滴油異常，平均會拖延2天才被人工發現，系統自動判斷可將發現時間提前到風險分數超標的當下，此「提前發現時間」可套用BRD-02既有的MTTR/停機成本邏輯換算節省金額。

**交接結構化的價值**：假設一次交接內容不完整，導致下一班多花15分鐘釐清狀況，系統自動標記不完整交接可讓管理者針對性介入，將此隱性成本顯性化。

## 市場定位
不是取代企業既有MES/CMMS系統的完整平台，而是給沒有預算或規模導入完整CMMS的中小型製造業，作為異常判斷與交接紀錄的輕量級補強層。

## 一頁電梯簡報
中小型製造業很多還在用紙本或LINE群組做設備保養判斷和班別交接，這些依賴的是老師傅的經驗和記憶，沒辦法規模化也沒辦法留下紀錄。我用自己在產線上驗證過的規則，加上n8n自動化和LLM輔助，做了一個輕量級工具，把這兩件事變成自動判斷、自動整理、有紀錄可查的流程。這不是要取代企業既有系統，是給還沒有預算導入完整CMMS的工廠一個補強層。
